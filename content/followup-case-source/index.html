CASE 01 / REAL-WORLD OPERATIONS TOOL
FollowUp / 装修业务运营台

把散落的业务状态，
收到工作台里。

一家小装修公司没有成百上千个客户，
但一单会持续几个月。

FollowUp 在专用电脑上只读同步微信，
把客户、工地和账目整理进同一个运营入口，
再把今天该处理的事情送回来。

负责人仍然决定怎么跟进和回复。
系统负责减少反复翻聊天、重新恢复上下文的时间。

01 / THE ACTUAL PROBLEM

客户不算多，
事情却很容易散掉。

一次装修合作会从需求、量房、方案和报价一路延续到施工、工人和款项。信息不是找不到，只是一直散在聊天与负责人的记忆里。

真正反复发生的动作不是“写一句更好的回复”，而是隔几天再回来时，要重新判断：上次聊到哪里、谁在等谁、这个工地卡在哪、最近有没有先垫出去一笔钱。

所以这页不从“做一套 CRM”开始，而从一个更现实的问题开始：怎么让状态自己留下来，而不是每次重新找回来。

第一版很小：聊天截图 → 信息提取 → 回复草稿。后来发现消息发完，业务状态并没有留下，于是核心对象从“一次聊天分析”改成“持续更新的客户与工地”。
01微信业务会话需求 / 报价 / 反馈
02客户跟进阶段 / 下一步 / 提醒
03工地进度环节 / 状态 / 备注
04工地账目垫账 / 实际支出
02 / INPUT

如果需要负责人认真维护，
它就不会被长期使用。

早期版本已经能存客户状态，但逐个建档、粘聊天、补字段、设提醒，只是把“记住事情”换成了“维护系统”。于是输入被拆成两种：第一次靠理解，之后靠增量。

ONGOING / INCREMENTAL UPDATE

之后更新，只处理新出现的内容。

微信出现新消息后，系统只读检查新增内容，按消息编号合并成业务会话摘要，再由负责人确认分类或关联对象。

    IMPLEMENTATION / 01

    检查本机微信数据变化

    Windows 定时任务调用只读同步脚本，先比较微信数据库文件的更新时间；源数据没有变化时，不重复解密和跑 ETL。

    边界只读同步和自动发微信是两件事。当前版本不控制微信客户端，不替负责人回复，也不会自动承诺价格和工期。

    当前部署频率：每 30 分钟检查一次变化。

    03 / OUTPUT

    让需要被处理的东西，
    自己出现。

    信息进来以后，如果还要专门打开一套系统寻找待办，负担并没有真正消失。FollowUp 用“今日页 + 晨间日报”把同一份本地状态变成两个很轻的出口。

    04 / AFTER SIGNING

    签约之后，
    业务只是换了组问题。

    客户进入施工阶段后，重点从“下次什么时候联系”变成“现在施工到哪、有什么问题、最近垫了什么钱”。这里没有做完整项目管理，只保留负责人每天真的会看的状态。

    05 / AI'S PLACE

    项目继续运行后，
    模型负责的事情反而少了。

    非结构化输入需要理解；重复、稳定、可验证的更新则不该每次都重新问模型。这里的变化不是“去 AI 化”，而是把模型留在更适合它的位置。

    01 / 第一次建库

    输入不规整，模型承担更多理解工作。

    截图和临时补充先被整理成客户卡。金额、日期、姓名等高影响字段仍由负责人确认。

    02 / 进入日常之后

    稳定的搬运和提醒，交回脚本与规则。

    模型按需处理新截图、零散文字和回复草稿；微信同步、到期判断与日报不必每次重新问模型。

    FIRST SETUP / 第一次建库

    先理解，再由人确认。

    AI
    主要负责截图、文字理解、客户卡整理
    增量脚本
    少量参与尚未进入持续更新
    固定规则
    少量参与校验基础结构
    负责人
    最终确认高影响字段与保存

    职责变化示意，不代表工作量统计。

    06 / CURRENT STATE

    它已经进入日常工作，
    也还在继续长。

    当前版本只服务一个负责人，没有急着做成通用 CRM。重点仍然是把真实业务里的记录与提醒跑顺，再决定下一步应该长什么。

    01运行环境

    负责人专用 Windows 主机，通过私有网络访问。

    02同步节奏

    微信只读同步任务每 30 分钟检查一次变化。

    03共享状态

    今日页、客户、工地和晨间日报读取同一份本地数据。

    04当前范围

    单负责人；多人权限、完整财务核销和施工协同尚未加入。

    WHAT IS NEXT / NOT YET PRODUCT

    下一步更值得验证的，不是再加一排字段。

    目前更想继续看两件事：完整话术怎样在本地处理，以及客户与工地积累下来的材料，怎样变成之后还能再次使用的业务知识。

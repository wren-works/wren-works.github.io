# 作品集 Case 表达

目标是让读者容易找到：发生了什么、作者做了什么、结果如何、什么结果改变了后续动作。

## 根据请求工作

- 用户要求审查、诊断或比较时，只分析，不擅自改文件。
- 用户明确要求改写，且范围清楚时，直接修改。
- 范围或作者基线会显著影响结果时，先说明假设；只有无法安全判断时再询问。

不强制先审后改，也不使用固定输出格式。

## 内部检查

审查正文或准备修改前，读取 [references/expression-rubric.md](references/expression-rubric.md)，在内部回答四个问题。根据用户关心的内容组织反馈，不必逐项展示。

## 修改原则

- 保住事实、数据、关键因果和结论强度；不要虚构动作、反馈或个人经历。
- 先解决用户指出的问题，再处理附近确实影响理解的语病、重复或绕句。
- 原句已经能承担作用时，优先局部修补；需要重写时也不必刻意保留原句结构。
- 逻辑能被读者自然推断，就不补齐所有连接词和总结句。
- 让具体动作和关键判断容易找到，但不要把“事实—分析—结论”写成固定段落模板。
- 已知可靠作者基线时，保留其常用词、句长、停顿、主观判断和不妨碍理解的局部不工整。
- 作者基线不可靠时，不猜测作者性，也不主动添加口头禅、自嘲或情绪。
- 少量旁注、轻微重复和低信息句可以承担节奏或视角，不因信息密度低就自动删除。
- 限制声明保留到足以避免误解即可；是否集中、移动或删除取决于上下文。

需要校准写作节奏时，读取 [references/case-style-layer.md](references/case-style-layer.md)。其中示例用于比较效果，不是必须模仿的句式。

需要延续这位作者已经确认的表达偏好时，读取 [references/author-preferences.md](references/author-preferences.md)。这些偏好只用于定向写作和修改；盲评、版本比较或其他作者的文案不默认加载。当前任务和用户最新指令始终优先。

## 交付

说明改动范围和重要取舍。只有确实压缩了会影响理解的技术细节时，才单独标记。

## 盲评

使用本 Skill 的 agent 已知评价框架，不充当盲评者。需要盲评时，准备匿名、等格式的 A/B 材料，交给未接触本 Skill 和修改方向的新 agent。
